# Minecraft: Story Mode — PS Vita

Unofficial PS Vita loader for the Android PowerVR build of *Minecraft: Story Mode*.

[Download](../../releases/tag/v1.10) — [Report a problem](../../issues/new?template=bug-report.yml) — [Discord](https://discord.gg/EYYTxeXCq)

| | |
| :-- | :-- |
| Loader | MCSM 1.10 prerelease |
| Data builder | v1.9 |
| Supported Android set | PowerVR v1.37 (`40137`) |
| Data path | `ux0:data/mcsm` |
| Licence | GPL-3.0 |

No Android game files are included. You must supply your own APK, main OBB, patch OBB, and any episode files.

## Current release status

1.10 is a public prerelease. Two things to know before installing:

- **The shipped VPK is `MCSM-1.10-logging.vpk`, a logging build.** It runs slower than a normal build, so performance measured on it is not representative. It writes `ux0:data/mcsm/loader.log`, which is what allows a fault to be traced instead of guessed at. See [Sending a log](#sending-a-log).
- **The progcache is incomplete.** The build compiles shader programs as you play, so a scene you have not reached before will stutter the first time.

## Setup

### 1. Install the loader

Install `MCSM-1.10-logging.vpk` with VitaShell.

### 2. Build the data folder

Run `MCSM-Vita-Data-Builder-v1.9.exe` on Windows.

1. Leave the mode on **Full setup**.
2. Press **Scan folder** and select the folder containing your Android files.
3. Confirm the APK, main OBB, and patch OBB are marked as verified PowerVR v1.37 files.
4. Leave **Balanced** selected unless you want another graphics profile.
5. Add any owned Episodes 2–8 now, or add them later.
6. Press **Build Data Folder**.

### 3. Copy the data to the Vita

Copy the finished `mcsm` folder into `ux0:data/`. The result must contain `ux0:data/mcsm/assets` and `ux0:data/mcsm/settings`.

### Adding episodes later

You do not need to rebuild the base data.

1. Select **Add episodes only** in the builder.
2. Add chapter folders, PowerVR chapter OBBs, ZIPs, or full nested bundles.
3. Press **Build Chapter Pack**.
4. Copy the resulting `mcsm` folder into `ux0:data/` and choose Merge or Replace in VitaShell.

A chapter pack contains only the selected chapter assets. It does not touch your saves, settings, or preferences.

## Sending a log

Attaching a log to a report is the single most useful thing you can do for this prerelease.

1. Play until the problem happens.
2. Close the game. Press PS, then close it from the LiveArea.
3. Do not launch the game again yet. The log is wiped at the start of every launch, so relaunching destroys the evidence you just captured.
4. Copy `ux0:data/mcsm/loader.log` off the Vita. Either open VitaShell and press SELECT to start its FTP server, or copy the file with VitaShell's file browser.
5. Attach it to a [bug report](../../issues/new?template=bug-report.yml) or post it in [Discord](https://discord.gg/EYYTxeXCq).

Send the whole file rather than a screenshot of part of it, and zip it first if it is large. The useful part is usually the last few hundred lines before the failure, but the earlier lines record which settings and chapters were loaded.

To disable logging without changing builds, add `logging = off` to `ux0:data/mcsm/settings/game.txt`.

## Reporting problems

Please report any problem, not only crashes. That includes freezes, dead stops, input problems, missing choices, saves or settings not persisting, language problems, audio delay, broken graphics, and severe performance drops.

Use the [bug report form](../../issues/new?template=bug-report.yml) or post in [Discord](https://discord.gg/EYYTxeXCq). Include:

- the episode and the exact scene or checkpoint
- what happened, and what you expected instead
- whether it happens every time
- your graphics profile and resolution
- any installed plugins, especially CapUnlocker or overclock tools

Never upload proprietary game assets, APKs, OBBs, or saves containing private information.

## Settings

There are exactly two settings files, both in `ux0:data/mcsm/settings/`:

| File | Contents |
| :-- | :-- |
| `graphics.txt` | `profile` (quality, balanced, performance, battery, custom) and every performance and visual lever |
| `game.txt` | Language, episode list, logging, audio gain, trophy options |

Anything not listed in a file keeps its default, so both files can be as short as one line. Older builds scattered these settings across roughly twenty single-purpose files such as `nolog.txt` and `mipmaps.txt`. Those are gone, and are ignored if present.

Two settings are worth knowing about:

- `outlines = off` in `graphics.txt` skips the per-mesh toon-outline pass. It is the largest single draw-count saving available, so it is the first thing to try if crowded scenes run badly.
- `logging = off` in `game.txt` disables the log, as described above.

## Trophies

Trophy support requires [NoTrpDrm](https://github.com/Rinnegatamante/NoTrpDrm/releases/tag/v.1.1) under `*KERNEL`.

If an older test build left a broken trophy registration:

1. Install [Trophy Manager v1.03](https://github.com/ONElua/TrophyManager/releases/tag/1.03).
2. Disable Wi-Fi and delete only the Minecraft: Story Mode trophy set.
3. Open the normal Vita Trophies app once, then reboot.
4. Reinstall the latest VPK.

Do not manually delete files from `ur0:user/.../trophy`. That leaves the trophy database inconsistent.

## Known limitations

- New scenes stutter while missing progcache entries compile.
- Crowded scenes can fall to roughly 20 FPS even when the target is 30 or 60 FPS.
- First boot can remain black for around 30 seconds while caches are created. An indefinite black screen is not normal; please report it.
- Settings and choices do not reliably persist across restarts. This is known and being worked on.
- All features still need broader real-hardware coverage across Episodes 1–8.

## Building from source

The loader requires the softfp VitaSDK with vitaGL, vitaShaRK, mathneon, and kubridge. A hard-float SDK is rejected.

```powershell
$env:VITASDK = "C:\path\to\vitasdk-softfp"
.\build_vpk.ps1
```

The output is `build_local/MCSM-1.10.vpk`. Build the Windows data preparer with `.\data-builder\build.ps1`; further detail is in [data-builder/README.md](data-builder/README.md).

VPKs, extracted game data, and proprietary Android files are excluded from source control.
